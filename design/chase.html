Decisions and how they fit the system

Why this layout

  • Ranked by days past the limit, with the dot plot on one scale, so urgency is visible down the left edge.
  • The tick is the order's own rule. A 3-day wait for a confirmation is as late as a 12-day wait for tracking, and the plot shows both fairly.
  • "Chased recently" is a separate quiet panel, so the repeat rule is visible instead of silently hiding rows.
  • One filled button: send every due message to the Outbox.

How it connects to the code

  • domain/chase.py already holds the three rules. It returns which alerts apply for an order and a date.
  • A new service filters those through AlertLog: if the same kind was sent in the last 2 days, the order goes to "Chased recently" with its next date.
  • Preview, Copy and Outbox all use domain/messages.py, so the three never disagree.
  • Adding to the Outbox writes an Outbox row and an AlertLog row in one transaction.

Rules and honest limits

  • The Outbox is test mode only. Nothing leaves the machine, as the SOP asks.
  • Confirmation starts at 2 days after ordering. Days use store time, America/Denver.
  • An order can have more than one reason at once. The list shows the most overdue one and the row opens to the rest.
  • Suppliers log in separately and never see this page.
