Decisions and how they fit the system

Why this layout

  • The unmatched queue comes first. Everything else on the page is history.
  • The matched-to column is a small stacked bar in the blue stage ramp, so spill-over shows without reading names.
  • "Not from an order" is gray and unmatched is dashed, so neither is confused with an order.
  • The only filled button is Record arrival, the main action here.

How it connects to the code

  • domain/matching.py: a pure function, open orders oldest first plus units in, allocations out. The preview and the saved result use the same function.
  • An arrival writes one Arrival, several Allocation rows (order_id empty means not from an order) and one StockMovement of kind arrival.
  • Editing a match deletes and rewrites that arrival's allocations and adds a reallocation movement. Stock does not change.
  • Order stages come from allocations, so the Orders page updates by itself.

Rules this screen must follow

  • Open means not cancelled and not closed, with units still to come (SOP section 4).
  • Oldest order first, by order date, spilling into the next.
  • Units beyond all open orders are unmatched, not lost. Warehouse stock still goes up.
  • Modals are native dialogs opened by an HTMX swap into the modal host, as with the other dialogs.
