Decisions and how they fit the system

Why this layout

  • One step line answers "why this number" better than a table. The table is one click away for exact values.
  • The runway is a drawer under the row, not a new page, so staff stay in the ranked list while comparing products.
  • Log adjustment is a quiet button. The one filled button stays on the reorder action of the Stock page.
  • Movement kinds use an icon and a word, never color alone.

How it connects to the code

  • The history is the StockMovement table: kind, delta, note, at, by. Stock after each row is a running total computed in the service, not stored.
  • Kinds: arrival, sale, adjustment, reallocation. A reallocation has delta 0 and names the orders.
  • app/charts.py gets a step-line function. The runway reuses forecast.py for burn and the order dates from orders.py.
  • Log adjustment writes one movement and changes Product.stock in the same transaction.

Rules and honest limits

  • An adjustment cannot take stock below zero.
  • The runway assumes each order lands on order date plus lead time. The SOP has no expected-date field, so this goes in the design note.
  • Past days of the chart come from movements, so older seed data without movements show a flat line. The seed adds starting movements to avoid this.
